# คลังข้อสอบและชุดสอบ

- วิทยาศาสตร์ ป.4–6 และ ม.1–3; วิทยาการคำนวณ ม.1–3: กลุ่มละ 100 ข้อ (เดิม 30 + ใหม่ 70)
- ข้อใหม่อยู่ใน `data/pool-*.tsv`: โจทย์ | เฉลย | ตัวลวง 3 ตัว มีเฉลยหนึ่งตัวต่อข้อ
- `node scripts/build-pools.mjs` ตรวจจำนวน/ตัวเลือก/ข้อซ้ำในแต่ละไฟล์ และสร้าง SQL แบบกำหนด ID คงที่ พร้อมกระจายตำแหน่งเฉลย
- `node scripts/test-pools.cjs` ทดสอบ SQLite ในหน่วยความจำ ไม่เปลี่ยนฐาน production

## การใช้งาน

ชุดเดิมเป็นคลังต้นทาง ครูแก้จำนวนที่ใช้สอบและเวลาได้ที่หน้ารายละเอียด ค่าเริ่มต้นชุดเดิมยังเป็น 30 ข้อ การเปลี่ยนจำนวนมีผลกับรอบใหม่เท่านั้น

ตอนสร้างชุดใหม่ เลือกคลังต้นทางและจำนวนที่ใช้สอบ ห้องเรียนต้องอยู่ชั้นเดียวกับคลังและวิชาต้องตรงกัน ชุดใหม่อ้างอิงคลังเต็มด้วย `bank_exam_id` ไม่คัดลอกแค่ตัวอย่าง 30 ข้อ เพิ่มข้อใหม่ที่คลังต้นทาง ไม่ใช่ชุดที่อ้างอิงคลัง

การสุ่มพยายามรักษาสัดส่วนหัวข้อในคลังและเลือกข้อที่ยังไม่เคยเห็นก่อน เมื่อข้อใหม่ไม่พอจึงกลับมาใช้ข้อที่เคยเห็น โดยไม่ซ้ำภายในชุด

- สลับหน้าจอ: คงข้อที่ตอบและข้อที่เปิดอยู่ พร้อมตำแหน่ง/ลำดับตัวเลือก สุ่มแทนเฉพาะที่เหลือ
- ครูสุ่มใหม่: ล้างคำตอบ เริ่มเวลาและพฤติกรรมใหม่ ตามจำนวนที่ตั้งล่าสุด; ประวัติข้อที่เคยเห็นยังอยู่
- กลับเข้ารอบเดิม: โหลด snapshot และคำตอบเดิม ไม่สุ่มใหม่
- ตรวจคะแนนตาม snapshot ที่ได้รับ พร้อมเฉลยเก็บเฉพาะฝั่งเซิร์ฟเวอร์ ไม่ส่งเฉลยให้ API นักเรียน
- ป้องกันแก้/ลบข้อที่อยู่ใน snapshot รอบสอบ ให้เพิ่มข้อใหม่แทน เพื่อไม่ให้ choice ID/คำตอบเดิมเสีย

ชุดพิมพ์ออฟไลน์ถูกสุ่มครั้งเดียวต่อการโหลดหน้า ใช้จำนวนที่ตั้งไว้ โจทย์และกระดาษคำตอบอ้างอิงชุดเดียวกัน อย่า reload ระหว่างพิมพ์เอกสารทั้งสอง กระดาษคำตอบแบ่งหน้าเมื่อเกิน 60 ข้อ

## ลำดับ deploy

1. ตรวจ schema แล้วเพิ่ม `0006_question_pool.sql` ก่อน deploy โค้ด (migration นี้เป็น ALTER TABLE อย่ารันซ้ำ)
2. Build/test/push และรอ Cloudflare ยืนยัน deploy สำเร็จ
3. เพิ่มเนื้อหาด้วย `0007_expand_question_pools.sql` แล้วตรวจแต่ละคลัง 100 ข้อและเฉลยหนึ่งตัวต่อข้อ (เนื้อหาใช้ INSERT OR IGNORE รันซ้ำได้)

โปรเจกต์นี้เคยรัน migration บางไฟล์โดยตรง จึงต้องตรวจ schema และ migration ledger จริงก่อนใช้คำสั่ง apply ทั้งชุด ห้ามสมมติว่า ledger ตรงกับ schema
